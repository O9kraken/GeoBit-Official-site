# Сервер и деплой

Сайт работает на VPS в Москве (Рег.облако, Ubuntu 24.04, 1 vCPU / 2 ГБ). Образ собирается в GitHub Actions, сервер только запускает готовое.

## Как идёт деплой

1. Пуш в `main`.
2. `.github/workflows/deploy.yml` собирает Docker-образ и публикует его в `ghcr.io/<владелец>/<репозиторий>`.
3. По SSH на сервере в `/opt/geobit/.env` прописывается новый `APP_IMAGE`, затем `docker compose pull && docker compose up -d`.
4. При старте приложение само применяет миграции базы (`src/migrations/`).

Секреты репозитория (Settings → Secrets → Actions): `SSH_HOST`, `SSH_USER`, `SSH_KEY`. Переменная репозитория: `DEPLOY_TARGET=vps`.

## Что на сервере

`/opt/geobit/`:

| Файл | Что это |
|---|---|
| `docker-compose.yml` | Приложение, PostgreSQL 18, Caddy |
| `Caddyfile` | HTTPS (Let's Encrypt), сжатие, кэш статики, реальный IP клиента в `X-Real-IP` |
| `.env` | Секреты: `PAYLOAD_SECRET`, `POSTGRES_PASSWORD`, `SMTP_*`, токены ботов. **Никогда не коммитится** |
| `scripts/backup.sh` | Резервная копия базы, cron `15 4 * * *` |

Доступ к серверу — только по SSH-ключу, пароли отключены, открыты порты 22, 80 и 443.

## Первая установка (для справки)

```bash
curl -fsSL https://get.docker.com | sh
mkdir -p /opt/geobit/scripts && cd /opt/geobit
# docker-compose.yml, Caddyfile, scripts/backup.sh и .env (по образцу .env.example)
echo <токен GitHub с read:packages> | docker login ghcr.io -u <логин> --password-stdin
docker compose up -d
```

## Заявки и персональные данные

- Заявки сохраняются в базе на сервере в России, полные данные приходят на почту через SMTP российского сервиса.
- В Telegram и MAX — только номер заявки и ссылка в админку, без имени и телефона.
- Защита форм: скрытое поле, проверка времени заполнения, не больше 5 отправок за 10 минут с одного IP.
- Заявки старше 3 лет удаляются автоматически раз в сутки (Политика, п. 7.1).

## Контент через миграции

Тексты, которые нужно залить на боевой сайт без ручной работы в админке (статьи, документы, страницы городов), лежат в `src/content/` и ставятся миграциями. Миграции создают только отсутствующее и не перезаписывают правки из админки.

## Редиректы

- Адреса страниц совпадают со старым сайтом на WordPress.
- `/wp-content/uploads/…` → 301 на `/media/…`.
- `/feed/`, `/author/…`, `/*-sitemap.xml` → 301 (`next.config.ts`).
- Свои редиректы — в админке: «Настройки → Редиректы».
